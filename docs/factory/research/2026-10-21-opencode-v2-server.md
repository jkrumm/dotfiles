## Bottom line

- **The server is two APIs on one process, not one.** Besides the v1 flat routes you already drive (`GET /session`, `POST /session/:id/abort`, `GET /event`, `GET /doc`, `GET /lsp`), it also serves a location-scoped v2 `/api/*` surface of 139 endpoints generated from `packages/protocol/openapi.json`; a running server publishes its OpenAPI 3.1 spec at `GET /doc`, and that spec is what the SDK is generated from.
- **Most useful things you do not use yet:** the durable per-session event log `GET /api/experimental/session/{id}/log?after=<seq>&follow=true`, the first-class inbox (`GET /api/session/{id}/inbox`, `PATCH`/`DELETE …/inbox/{id}`, `delivery: "steer" | "queue"`), `POST /api/session/{id}/interrupt?resume=`, the permission-reply API, session forms, staged revert, session export/import, and `POST /api/session/{id}/background`.
- **Extensibility** is agents-as-markdown-or-config plus a `task` subagent tool (V2: `subagent`), plugins via `Plugin.define({id, setup(ctx)})` from `@opencode/plugin` with per-domain hooks, MCP via config plus a runtime API, custom tools as files in `.opencode/tools/`, and LSP/formatters that are opt-in config — and that **V2 no longer runs LSP**.
- **In the last three months** OpenCode 2 became a separate published line (`@opencode/cli` / `@opencode/client` 2.1.2, 2026-10-21) while the GitHub "latest release" stayed 1.x (v1.19.3, 2026-10-16); V2 ships three intentional breaking changes plus broad config renames, 1.19.1 discontinued session sharing, and 2.1 further breaks SDK/HTTP/plugin contracts including removal of `session.compacted`.
- **Fitness:** the pieces worth adopting for a control plane are the durable per-session log, inbox/steer and interrupt-with-resume, external permission reply, and transcript export; the orchestration layer must still build its own global job queue, approval escalation/timeouts, webhook delivery and tenancy, and the unreliability reported against 1.18.4 needs re-testing on your version.

## 1. HTTP API surface, domain by domain

**Spec/SDK:** `GET /doc` serves the OpenAPI 3.1 spec ("HTML page with OpenAPI spec") and is the source the SDK is generated from (https://dev.opencode.ai/docs/server/). The v2 reference is itself an OpenAPI 3.1.0 document titled "HTTP API — Experimental HttpApi surface for selected instance routes" (https://opencode.ai/v2/docs/api); the route inventory totals 139 endpoints in 10 audited groups (https://github.com/anomalyco/opencode/blob/HEAD/V2_HTTP_API_AUDIT.md).

**Messages / prompt / queue.** `POST /api/session/{sessionID}/prompt` takes `{id?, text (required), files[], agents[], skills[], metadata, delivery, resume?}` and "durably admit[s] one session input" (https://opencode.ai/v2/docs/api). Delivery enum is `Session.Inbox.Delivery` = `"steer" | "queue"` (https://opencode.ai/v2/docs/build/plugins). Queue is first-class: `GET …/inbox` lists "durable enqueued session work not yet delivered, ordered by enqueue sequence"; `PATCH …/inbox/{inboxID}` changes delivery mode where "Steering wakes session execution"; `DELETE …/inbox/{inboxID}` cancels undelivered input. Read side is `GET …/message` with `limit/order/cursor/type` (types include `user, assistant, compaction, idle, system, synthetic, skill, shell, agent-switched, model-switched, location-switched`) and `GET …/message/{messageID}`; no message-update route appears in either v2 source, so treat that absence as provisional.

**Interrupt.** v2: `POST /api/session/{sessionID}/interrupt?resume=true|false` → `{interrupted: boolean}`; `resume` "resumes pending steering input and next-in-line control items… while queued prompts remain parked" (https://opencode.ai/v2/docs/api). v1: `POST /session/:id/abort` → boolean, plus `POST /session/:id/prompt_async` → 204 (https://dev.opencode.ai/docs/server/).

**Events.** v1 has two global SSE endpoints (`GET /event`, first event `server.connected`; `GET /global/event`) and no per-session stream (https://dev.opencode.ai/docs/server/). v2 `GET /api/event` is "across all server locations" and "volatile by contract: a slow consumer overflows and fails the stream, and events during disconnection are missed" (https://opencode.ai/v2/docs/api). The durable, replayable stream is per-session: `GET /api/experimental/session/{sessionID}/log?after=<Event.Seq>&follow=true`, "reads events after an exclusive aggregate sequence and continues with live events when follow=true" (same source).

**Permissions.** `GET /api/permission/request`, `GET /api/permission/saved`, `PATCH|DELETE /api/permission/saved/{id}`, `GET|POST /api/session/{sessionID}/permission`, `GET …/permission/{requestID}`, and `POST …/permission/{requestID}/reply` with `{decision: Permission.Reply, message?}` → 204 (https://opencode.ai/v2/docs/api). v1 is `POST /session/:id/permissions/:permissionID` `{response, remember?}` — the audit records the field rename `response` → `decision` (https://dev.opencode.ai/docs/server/). Rulesets are attached to the session itself (`permissions: Permission.Ruleset` on `POST /api/session` and `PATCH /api/session/{sessionID}`) (https://github.com/anomalyco/opencode/blob/HEAD/V2_HTTP_API_AUDIT.md).

**History / compaction / fork / revert.** `POST …/compact` (`{id?, delivery?}`, "steers by default: it runs at the next step boundary"), `GET …/context` (messages after last compaction), `GET …/diff?from&to&context`, `POST /api/experimental/session/{id}/wait` (https://opencode.ai/v2/docs/api). v2 fork is `POST …/fork {before?}`; revert is three calls — `POST …/revert/stage {messageID, files?}`, `POST …/revert/commit`, `DELETE …/revert` — all returning `409 SessionBusyError` when busy; v1 has `POST /session/:id/fork`, `/revert`, `/unrevert`, plus `/init` and `/summarize` with no v2 counterpart (https://dev.opencode.ai/docs/server/). No snapshot/checkpoint endpoint exists; the only "snapshot" route is the persistent-PTY screen snapshot (https://github.com/anomalyco/opencode/blob/HEAD/V2_HTTP_API_AUDIT.md).

**Files.** v2: `GET /api/fs/read/*` (ETag/Last-Modified, single-range 206/416/304), `GET /api/fs/list?path=`, `GET /api/fs/find?query&type&limit`, `POST /api/experimental/fs/write?path=` (raw body, not confined to the location) (https://opencode.ai/v2/docs/api). Content grep, `file/status` and symbol search exist only on v1 (`GET /find?pattern=`, `/find/file`, `/find/symbol`, `/file/content`, `/file/status`) — v2 `fs.find` matches names, not file contents (provisional, low) (https://dev.opencode.ai/docs/server/).

**LSP / formatter.** v1 only: `GET /lsp` (`LSPStatus[]`), `GET /formatter`, and `GET /experimental/tool/ids` / `/experimental/tool` (https://dev.opencode.ai/docs/server/). Neither appears in the v2 inventory (provisional, low), and the migration guide states V2 "stops running language servers" — `lsp` config is accepted but yields no LSP tools or diagnostics (https://opencode.ai/v2/docs/migrate-v1/).

**Config / agents / MCP / plugins.** `GET /api/info`, `/api/config`, `/api/config/shell`, `PATCH /api/experimental/config` (accepts only `shell` initially), `/api/agent[/{id}]`, `/api/mcp` plus `PUT|DELETE /api/experimental/mcp/{server}` and `…/connect`, `…/disconnect`, `GET /api/mcp/resource`, `/api/model[/default]`, `/api/provider[/{id}]`, `/api/plugin` (+`/check`, `/update`), `/api/credential`, `/api/integration`, `/api/location` (+`reload`), `/api/project`, `/api/worktree` (+`refresh`), `/api/vcs/*`, `/api/websearch`, `/api/rpc/{rpcID}/{method}`, `POST /api/pair` + `GET /auth/connect/{code}` (https://opencode.ai/v2/docs/api, https://github.com/anomalyco/opencode/blob/HEAD/V2_HTTP_API_AUDIT.md). v1 equivalents are flat: `GET /config`, `GET /mcp`, `POST /mcp {name, config}`, `GET /agent`, `GET /provider`, `PUT /auth/:id` (https://dev.opencode.ai/docs/server/).

**Control surfaces.** v1 exposes TUI driving over HTTP (`/tui/append-prompt`, `/tui/submit-prompt`, `/tui/execute-command`, `/tui/show-toast`, plus `GET /tui/control/next` + `POST /tui/control/response`) (https://dev.opencode.ai/docs/server/). v2 replaces that with PTYs (`/api/pty`, `GET /api/pty/{id}/connect` WebSocket, `POST …/connect-token`), persistent PTYs, `/api/shell` + `/{id}/output`, and human-in-the-loop **forms** (`GET|POST /api/session/{id}/form`, `…/form/{formID}`, `POST …/form/{formID}/reply`, `DELETE …/form/{formID}`, location-wide `GET /api/form`) (https://opencode.ai/v2/docs/api).

**Other v2-only session controls:** `PUT …/environment {variables}`, `POST …/view`, `…/synthetic`, `…/shell`, `…/command`, `…/model` and `…/agent` (switch for subsequent turns), `…/move {directory, delivery?}`, `…/background`, `GET /api/session/active`, `POST /api/experimental/generate`, instruction entries, `session.import|export|stats` (https://opencode.ai/v2/docs/api).

**Share.** No share/unshare route appears in the v2 inventory — only a `share: string` schema field (https://github.com/anomalyco/opencode/blob/HEAD/V2_HTTP_API_AUDIT.md); and 1.19.1 "discontinued session sharing" (https://opencode.ai/changelog.json). Treat v2 share as non-existent until proven otherwise.

## 2. Extensibility and configuration model

**Agents/subagents.** Two definition paths: `"agent": {name: {...}}` in `opencode.json`, or markdown with YAML frontmatter in `~/.config/opencode/agents/` and `.opencode/agents/` (filename = name). Keys: `description` (required), `mode` (`primary|subagent|all`, default `all`), `model`, `temperature`, `top_p`, `prompt` (`{file:...}`), `steps`, `disable`, `hidden`, `color`, `permission`; `tools` is deprecated in favour of `permission` (https://dev.opencode.ai/docs/agents/). Per-agent permission keys: `read, edit, glob, grep, list, shell, task, external_directory, webfetch, websearch, lsp, skill, question, doom_loop` each `"ask"|"allow"|"deny"`; `permission.task` gates which subagents may be launched and `deny` removes that agent from the Task tool description. Invocation is the `task` tool with `{description, prompt, subagent_type, task_id?, command?, background?}`; `background` requires `OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS=true` and nesting is refused at `cfg.subagent_depth ?? 1` — it creates a child session with `parentID: ctx.sessionID` and derives child permissions via `deriveSubagentSessionPermission` (https://github.com/anomalyco/opencode/blob/v1.19.3/packages/opencode/src/tool/task.ts). Over HTTP there is no "run agent X" endpoint — `GET /agent` lists, and `agent` is a body field on message/command/shell (https://dev.opencode.ai/docs/server/). V2 renames the model to `"agents"` with ordered `{action, resource, effect}` `permissions`, `system` instead of `prompt`, `disabled`, `default_agent`, and the `subagent` tool; `hidden` "controls visibility, not security" (https://opencode.ai/v2/docs/agents).

**Plugins/hooks.** Loaded from `.opencode/plugins/`, `~/.config/opencode/plugins/`, and `"plugin": [...]` (Bun-installed into `~/.cache/opencode/node_modules/`), order global config → project config → global dir → project dir (https://opencode.ai/docs/plugins/). Shape: `export const MyPlugin = async ({ project, client, $, directory, worktree }) => ({...hooks})`. The v1.19.3 `Hooks` interface: `dispose, event, config, tool, auth, provider, "chat.message", "chat.params", "chat.headers", "permission.ask", "command.execute.before", "tool.execute.before", "tool.execute.after", "tool.definition", "shell.env", "experimental.chat.messages.transform", "experimental.chat.system.transform", "experimental.provider.small_model", "experimental.session.compacting", "experimental.compaction.autocontinue", "experimental.text.complete"`; e.g. `"permission.ask"?: (input: Permission, output: { status: "ask"|"deny"|"allow" })` and `"tool.execute.before"` receives `{tool, sessionID, callID}` + mutable `{args}` (https://github.com/anomalyco/opencode/blob/v1.19.3/packages/plugin/src/index.ts). V2 switches to `@opencode/plugin`: `export default Plugin.define({ id, setup(ctx) })`, hooks per domain with one mutable event (`ctx.tool.hook("execute.before")`, `ctx.shell.hook("create.before")`, `ctx.session.hook("prompt"|"context"|"model.request"|"compaction")`, `ctx.permission.hook("evaluate")`), `ctx.event.subscribe()`, `ctx.storage`, cleanup returned from `setup` (https://opencode.ai/v2/docs/build/plugins/migrate-v1/, https://opencode.ai/v2/docs/build/plugins); four v1 hooks have no one-to-one V2 equivalent.

**MCP.** `"mcp": {name: {type: "local"|"remote", ...}}` — local: `command[]`, `cwd`, `environment`, `enabled`, `timeout` (5000 ms); remote: `url`, `headers`, `oauth` (`{}`/`false`/`clientId|clientSecret|scope`), `enabled`, `timeout` (https://opencode.ai/docs/mcp-servers/). Runtime: `GET /mcp`, `POST /mcp {name, config}` (https://dev.opencode.ai/docs/server/); V2 adds `PUT|DELETE /api/experimental/mcp/{server}` and connect/disconnect (https://opencode.ai/v2/docs/api). MCP tools are ordinary tools gated by glob, e.g. `"tools": {"my-mcp*": false}` (https://opencode.ai/docs/mcp-servers/).

**Custom tools.** `.opencode/tools/` or `~/.config/opencode/tools/`; `import { tool } from "@opencode-ai/plugin"`; `tool({description, args:{x: tool.schema.string()}, async execute(args, context)})`; filename = tool name, extra exports become `<filename>_<export>`, collisions override built-ins; `context` carries `{agent, sessionID, messageID, directory, worktree}` (https://opencode.ai/docs/custom-tools/). They can also be registered from a plugin's `tool` hook (https://opencode.ai/docs/plugins/). The Tools page's claim that tools are "defined in your config file" contradicts this; the file-based account is the detailed one (https://opencode.ai/docs/tools/).

**Events** (plugin `event` hook): `server.connected; session.created|updated|idle|status|error|diff|compacted|deleted; message.updated|removed; message.part.updated|removed; permission.asked|replied; file.edited; file.watcher.updated; lsp.client.diagnostics; lsp.updated; installation.updated; command.executed; shell.env; tool.execute.before|after; tui.prompt.append; tui.command.execute; tui.toast.show` (https://opencode.ai/docs/plugins/).

**LSP/formatters.** Both opt-in: `"lsp": true|{}|false` with entries `{command[], extensions[], disabled, env, initialization}`; `"formatter": true|{}|false` with entries `{command[], extensions[], disabled, environment}` and `$FILE` substitution (https://opencode.ai/docs/lsp/, https://opencode.ai/docs/formatters/).

## 3. What changed in the last ~3 months, and what "v2" is

`sst/opencode` now resolves to **anomalyco/opencode** (219,434 stars, default branch `dev`, last push 2026-10-21), whose GitHub "latest release" is still **v1.19.3** (2026-10-16) (https://github.com/anomalyco/opencode). Two npm lines run in parallel: `opencode-ai` **1.19.3** (last published 2026-10-16) and `@opencode-ai/plugin`/`sdk` 1.19.3 for V1 (https://www.npmjs.com/package/opencode-ai, https://www.npmjs.com/package/@opencode-ai/plugin); V2 publishes as **`@opencode/cli` 2.1.2** and **`@opencode/client` 2.1.2** (both 2026-10-21) (https://www.npmjs.com/package/@opencode/cli, https://www.npmjs.com/package/@opencode/client). `@opencode-ai/cli` exists but is stale at `0.0.0-beta-17823` (2026-09-07), so instructions to install `@opencode-ai/cli@beta` point at an outdated artifact (https://www.npmjs.com/package/@opencode-ai/cli). The repo default branch declares `"version": "2.1.2"` (https://github.com/anomalyco/opencode/blob/HEAD/package.json). "V2" denotes both product major and server API version — the v2 reference exposes `GET /api/experimental/migration/v1` for V1→V2 session-history migration (https://opencode.ai/v2/docs/api). A static machine-readable spec is also published; the full schema was not read (see unverified).

Exactly three intentional breaking changes: new plugin API, new server-API/client contracts (use `@opencode/client`), and TUI config collapsing from layered `tui.json(c)` into one auto-migrated `~/.config/opencode/cli.json` (https://opencode.ai/v2/docs/migrate-v1/). Config renames: `permission`→`permissions` (ordered action/resource/effect; `bash`→`shell`, `task`→`subagent`, `write`/`patch`→`edit`), `agent`/`mode`→`agents` (`prompt`→`system`, `disable`→`disabled`, `variant`→`model#variant`, `maxSteps`→`steps`), `snapshot`→`snapshots`, `attachment`→`media`, `command`→`commands`, `reference`→`references`, `provider`→`providers` (`npm`→`package` with `aisdk:` prefix, `api`→`settings.baseURL`), MCP under `mcp.servers` (`enabled` inverted to `disabled`, `timeout` split into `{catalog, execution}`), `compaction.keep.tokens`/`buffer`, `skills` as one ordered array, model `id`→`modelID` (https://opencode.ai/v2/docs/migrate-v1/). Silently ignored: `logLevel`, top-level `server`, `subagent_depth`, `compaction.tail_turns`/`prune`, several `experimental` flags; provider IDs consolidate (`azure-cognitive-services`→`azure`, `google-vertex-anthropic`→`google-vertex`) (same source).

V1 timeline in the window: 1.18.24 (2026-08-28) made V1 read supported V2 config fields; **1.19.0 (2026-10-11) added `opencode upgrade --major`**; **1.19.1 (2026-10-15) discontinued session sharing**; 1.19.2 (2026-10-16) pinned 1.x installs to 1.x (https://opencode.ai/changelog.json). Also 1.18.34 (2026-09-30) sends namespaced session and parent-session identity headers, 1.18.27 defaulted provider/stream timeouts to five minutes, and 1.18.20 made failed subagent tool calls resumable via `task_id` (same source). **2.1** breaks SDK/HTTP/plugin contracts again: `state`/`providerState`/`resultState`→`native`, `providerContext`→`native.messages`, `Credential.Key.configuration` removed for `metadata`, compaction `recent`→`metadata.keepID`, and the transitional **`session.compacted` event is removed** (https://opencode.ai/changelog). The v2 CLI defaults to one shared background server per user with `--standalone` / `--server <url>` overrides and `opencode service set disabled true` (https://opencode.ai/v2/docs/cli). Secondary reporting dates the 2.0 announcement to 2026-10-12 and the first stable 2.0.0 npm publish to 2026-09-11 (https://thenewstack.io/opencode-2-shared-service/, https://www.turboai.dev/blog/opencode-2-versions).

## 4. Fitness for autonomous review/implement/triage + a live control plane

**(a) Observability.** Build the control plane on `GET /api/experimental/session/{id}/log?after=<seq>&follow=true`, not on `/api/event`: the latter is documented volatile and drops events across disconnects (https://opencode.ai/v2/docs/api). Stream `message.part.updated` (tool-call parts), `session.status|idle|error|diff`, `permission.asked|replied` for progress (https://opencode.ai/docs/plugins/). No documented cap on concurrent SSE clients exists (https://dev.opencode.ai/docs/server/). **Caveat:** a report against 1.18.4 with plain curl found `/api/event` closing ~0.1–1.4 s after each flush with no replay, v1 `/event` emitting only heartbeats, only 4 of 88 declared V2Event types ever firing, and `POST /api/session/{id}/wait` returning `503 "Session wait is not available yet"` for HTTP-created sessions — retest against your release (https://github.com/anomalyco/opencode/issues/38458).

**(b) Permissions/approval.** Your control plane can be the approver: rules resolve `allow|ask|deny` with glob patterns and last-match-wins per tool and per agent, `--auto` approves anything not explicitly denied (https://opencode.ai/docs/permissions/); reply via `POST /api/session/{id}/permission/{requestID}/reply` with `{decision, message?}`, list via `/api/permission/request` and per-session routes, and persist "remember" choices through `/api/permission/saved` (https://opencode.ai/v2/docs/api). Inject per-job-class rulesets at `POST /api/session` / `PATCH /api/session/{id}` (https://github.com/anomalyco/opencode/blob/HEAD/V2_HTTP_API_AUDIT.md). There is no webhook: `permission.asked` must be watched on the stream or the endpoints polled, and no escalation policy/timeout/routing is documented (https://opencode.ai/docs/plugins/).

**(c) Safe mutation.** Staged revert is the rollback primitive: `POST …/revert/stage {messageID, files?}` → `POST …/revert/commit` or `DELETE …/revert`, all `409 SessionBusyError` when busy, so interrupt first (https://opencode.ai/v2/docs/api). Granularity is the message/turn boundary; `GET …/diff` "compares the range's first recorded snapshot with its last" and refuses ranges spanning a location change — snapshots are implicit, never a standalone create/name/restore API (https://opencode.ai/v2/docs/api).

**(d) Delegation.** Subagents are configurable subagents with `permission.task` globs, `hidden` for programmatic-only, and a `steps` cap (https://dev.opencode.ai/docs/agents/); each gets a child session (`POST /session {parentID}` to create one yourself, `GET /session/:id/children`, `?parentID=` filtering) (https://dev.opencode.ai/docs/server/). There is no per-child stream — observe via the session log/global stream plus `GET /session/status` and v2 `GET /api/session/active` ("foreground Session drains currently owned by this OpenCode process") (https://dev.opencode.ai/docs/server/, https://opencode.ai/v2/docs/api). Creating child sessions directly from your scheduler, rather than relying on the model's `task` call, is the cheap win.

**(e) Artifacts.** `GET /api/experimental/session/{id}/export` yields "a complete projected session transcript" (with `sanitize`) and `POST /api/experimental/session/import` replays earlier exports, parents before children — good triage/review artifacts (https://opencode.ai/v2/docs/api). Avoid share: 1.19.1 discontinued it (https://opencode.ai/changelog.json) and v2 has no share route (https://github.com/anomalyco/opencode/blob/HEAD/V2_HTTP_API_AUDIT.md).

**(f) Auth/isolation.** One process-wide credential: `OPENCODE_SERVER_PASSWORD` (basic auth, user default `opencode`, `OPENCODE_SERVER_USERNAME` override); v2 pairing (`POST /api/pair`, `GET /auth/connect/{code}`) returns a session token to use as the password (https://dev.opencode.ai/docs/server/). Isolation is the **location/directory**, not tenancy: nearly every v2 route takes `location`/`directory`, and `POST /api/location/reload` cancels pending permissions/forms for a location (https://opencode.ai/v2/docs/api). The SDK's `GlobalEvent` ("Event with directory context") matches that per-location model (https://anomalyco-opencode.mintlify.app/sdk/types).

**(g) What you must build.** A global job queue with priority/retry (only per-session `inbox` with delivery modes exists), webhook/callback delivery, approval escalation policy and timeouts, per-tenant authz/quotas, cross-session indexing beyond `session.list?search=` and `session.stats`, and per-session prompt serialization (`409 Conflict`). Forms (`POST /api/session/{id}/form` → `…/form/{formID}/reply` / `DELETE`) are the cleaner channel for triage questions that need a human answer rather than an approval (https://opencode.ai/v2/docs/api). Note also: V2 does not run LSP (https://opencode.ai/v2/docs/migrate-v1/) and todos are off by default behind `experimental.todo`, so a review job that relies on diagnostics must stay on 1.x behaviour or run its own analysis.

Not verified: whether `opencode serve` survives unchanged in V2 and with what flags; the full v2 schema (V2Event members, `Permission.Reply` enum, `Session.Inbox.Delivery` definition); V2's exact hook names beyond the domains listed; v1→v2 event-name migration lists; and the scope of `session.share`/`unshare`.
