1. Verdict

Rebuild warden as level-triggered reconcilers over one ledger, describe every repo in one manifest, take signals from their sources, and let verification — not the owner — gate every ship. Adopt no heavy runtime: beads, a workflow engine and Keep's model each lost a measured spike, and their designs are copied instead. The factory's real cost today is owner attention, not tokens: 577 owner-facing notifications and 50 "continue" nudges, against $2.60 of agent spend on the ten worst incidents.

The target in ten lines#

  1. One fresh ledger (ledger.db, history imported once from the archived warden.db) with an append-only event log; eleven nouns, one writer each.
  2. One project.yaml per repo; AGENTS.md routing, herdr groups, Argo's registry and reconciler policies are generated from it.
  3. Signals from their primary sources with source time; Slack intake retires source by source.
  4. Per-project reconcilers open and close Conditions; a webhook only schedules a reconcile.
  5. A correlator folds conditions by fingerprint, topology and time window into one incident per cause; closed incidents with a recipe are the known-error store.
  6. Tasks live in the ledger with a blocker-aware ready queue; mothers (six fleet projects) and sessions (everything else) work them through one spawner, rd.
  7. Every agent runs in herdr; engine by class (routine on OpenCode/IU, judgment on Claude Code/Max); quota is a scheduler input; Witness resumes parked agents.
  8. A verification ladder per action class authorises auto-ship; absent evidence fails closed to propose-only; rollback redeploys the last verified Deployment and squash merges keep the git revert mechanical; a breaker counted per lineage stops runaway loops without paging anyone.
  9. The owner decides four things only — product direction, spend, irreversible data loss, other people — each as a card with a default and an expiry; SLO: under 1 % of items reach him, stretch 0.1 %.
  10. Argo answers his 27 canonical questions and the brief's 3 from live read models on the mini; the VPS keeps the life pages and the off-site dead-man's switch.

3. Invariants (each one a CI check or a ledger constraint)#

  1. One writer per entity table: write functions live in one module per noun; a CI check rejects writes from anywhere else.
  2. Every state change emits its event in the same transaction (transactional outbox).
  3. Conditions close only on an observation.
  4. An Incident closes only after a pass Verification linked to it.
  5. A Decision with decider owner exists only for product direction, spend, irreversible data loss or other people, and always has a default and an expiry. Pause is not a Decision.
  6. A worker Agent has a hook before it runs; one live worker Agent per Task, fenced by its lease epoch (a stale epoch is rejected); one writer per checkout.
  7. A Change merges only when its action class's verification ladder is satisfied.
  8. Every pure read model can be rebuilt from the event log plus the manifests at each event's manifest_sha; effectors send each (event_id, channel) at most once, recorded in deliveries before the send, so a rebuild never re-sends.

2. Correlate — one cause, one incident#

  1. Fingerprint = a default per source (source + monitor/check id + normalised message) with per-source refinements written as {{default}} + field rules (Sentry's model): a rule refines, never replaces.
  2. Dedup: same fingerprint while its condition or incident is open → an occurrence.
  3. Topology: the manifests give host → container/job → service → project. Signals whose subjects share an ancestor inside the window fold under the ancestor's incident; deployments of that subtree inside the look-back window attach as suspects. A fold reaches the host only on host-level evidence — a boot record, a Beszel host-down, a Docker daemon event, or ≥ 50 % of the host's monitored subjects firing; otherwise it stops at service/project.
  4. Time windows (frozen on the golden set's development half, ADR-003): topology fold 45 min, recurrence 7 d; for stateful sources whose recovery signal closes the episode (Kuma Up, Beszel recovery) dedup 12 h, open incident 6 h, similarity fallback θ 0.2 within 4 h; for stateless sources (CI failures, log lines, issues) dedup ≤ 30 min, open ≤ 60 min. A longer link is an explicit, undoable edge the investigator proposes. A window is never the only key (a pure time window merges unrelated incidents — research ops-correlation §5). Held-out result: B-cubed P 0.937, R 0.846, F1 0.889 vs today's 0.744 — recall inside one burst, precision under the detach reading (ADR-003).
  5. Close by member: an incident closes only when every member's own Condition has resolved; a split operation detaches a member whose condition outlives the group, timeline kept.
  6. Act per incident: while a topology ancestor has an open host condition (boot, mount, reachability), child recipes are held for the host's hold window and the host runbook runs first.
  7. Candidate gate (Keep's promotion): a candidate becomes an incident when it persists ≥ T, or reaches N signals, or matches a known error, or its severity is critical; otherwise it expires as noise, recorded and scored.
  8. Known errors: a closed incident with a recipe (root cause, fixing change, action class, verification evidence). Every new incident is matched against them: exact fingerprint on a promoted recipe → reuse it within its action class's ladder; similar, or a recipe not yet promoted → the recipe goes into the investigator's brief. A recipe is promoted to automatic reuse only after its post-deploy hold confirms it (§3). The judgment calls — root cause, recipe choice, decision_class — belong to the investigate worker on OpenCode/IU; no single-shot decision model sits anywhere in this loop (ADR-003).
  9. Regression: a fingerprint recurring after its fixing change was deployed opens a new incident with regression_of, and the fixing change is the first suspect.

5. Agents#

  • Roles. Mother — one per fleet project, lean: turns the project's new Conditions, requests and plan items into Tasks and keeps its ready queue honest; never edits code. Lead — one per active plan or epic: sequences tasks, spawns workers, handles rebases and merge-train returns. Worker — an Agent carrying a task_id and its hook: implements, verifies, hands back a Change; a Task's attempts are its worker Agents. Session — a plain agent for session-class projects and ad-hoc work. Hermes — the conversational door: answers from read models, files Tasks, asks the spawner for sessions; never edits code.
  • One spawner. rd is the only code path that creates an agent: it writes the Agent record (with task_id for a worker), cuts the hook, delivers the brief, sets tab metadata.
  • The Agent carries the hook; the hook owns the work (Gas Town): worktree + branch + base sha + task notes. A dead or rotated agent's successor resumes from the hook, not from a re-prompt.
  • Lifecycle. spawn → work → done → reap (janitor). Rotation at the context mark: the agent writes its handover into the hook; the spawner starts the successor; the old one is reaped. Mothers rotate daily.
  • Gas Town, explicitly. Copy: the hook, Witness (the agent reconciler: stuck, zombie, finished-but-open), Refinery (the merge train that already exists), Deacon (reconcilers on patrol — as code). Reject: a global Mayor LLM (scheduling is code), idle LLM patrols (cost), convoys (Task dependencies suffice), tmux (herdr).

3. Information architecture#

Exception-first: when nothing is wrong, each surface says so in one line and stops. The shell never changes shape (rail, ambient status, one attention queue, detail on selection); the content does.

Freshness. Every read model returns as_of and its expected cadence. A source older than its cadence renders as a stale term in place of its value (quota stale since hh:mm, not a frozen Max 46 %); "all up" needs every health source fresh, so a dead collector can never produce it.

One slot per entity. Each entity renders in exactly one Home slot, picked by precedence decision > broken > parked > in flight: a stuck agent whose agent.stuck condition sits in an open incident shows under Broken, not again under Parked/stuck. Fixed alone is a count with a drill-down, never a list on Home.

D1 — How much IU cash may factory-originated work use? (spend)#

  • Why it is a decision now: owner-started work alone fills the Max window — fleet waves 74 % plus interactive sessions 32 % of a weekly window per week, 120 % in total over 30 days, 204 % over the last 7 (kpi/forecast). Factory judgment (mother and lead wakes, attempt ≥ 3 escalations) therefore runs on IU with a Claude-class model unless Max would otherwise lapse (ADR-008).
  • Measured: all IU today $147/week (agw tools $91, agw OpenCode $28, research $18, Hermes $4; kpi/forecast); warden-owned items cost ≈ $3.90/day (kpi/cost).
  • Projected at the forecast's assumption (336 wakes a week at ≈ $2.11 — an assumption, not a measurement): mothers and leads add ≈ $707/week; moving agw review off Max adds up to ≈ $469/week. Full design on IU: ≈ $1,320/week.
  • A — cap factory IU at ≈ $300/week (twice today's IU): mothers wake for briefs and unmatched conditions within a per-mother budget; non-urgent judgment queues; review stays on Max while the forecast allows.
  • B — ≈ $1,320/week: mothers and leads wake at the forecast rate; review moves to IU.
  • Tradeoff: ≈ $4,000 a month at the upper bound vs speed of autonomous judgment work; incidents are never capped either way.
  • Recommendation: A, then re-decide with 8 weeks of measured wakes and cost per action class × engine — the wake rate is the weak number (doubling it moves the Max-only projection from 142 % to 164 %).
  • Default: A from W4; expires 2026-12-31.

D2 — Raise the Claude subscription tier? (spend)#

11. FAQ

Why not just adopt beads, a workflow engine, or Keep? Each was measured on our data. beads v1.3.1 leaves cross-repo dependencies unenforced (0 of 9), fixes its lease at 5 minutes, and touches work repos even in contributor mode (spike 1). DBOS on SQLite survived every kill but strands flows on a redeploy and adds a second system of record (spike 2). Keep's model — fingerprint fields plus attribute rules, no topology — scored F1 0.737 on the held-out golden set, no better than leaving every event alone (0.740), against 0.889 for the proposed correlator (spike 3). What each does well is copied: bd's verbs and ready semantics, durable primitives, Keep's candidate gate.

Why not Mastra? It was not run, and ADR-002 records why: it is TypeScript-only, the research could not verify its durability, suspend/resume and timeout semantics, and it would add a TS runtime and a second system of record beside a Python loop.

What happened to the decision models? There is no single-shot decision model in the loop. Yours become the investigate worker on OpenCode/IU, making the judgment calls — which recipe, which decision_class (ADR-003). Measured as a single shot, the decision model agreed 92 % with warden's LLM triage but only 60 % with the true grouping (kpi/decision_shadow); deterministic rules group, the worker judges.

Is this a rewrite of warden? Yes — rewrite and cutover, no co-running. The old loop stops when W1 starts and its database is archived read-only; history enters a fresh ledger by one import. Each rewritten piece goes live when it passes its own proof gate (backtest, gamedays, holdouts, the timed Argo test). Only the build lane, your apps and their data, and the archived stores stay up throughout.

Why mothers at all, and why only six? A mother pays for itself where planned work arrives continuously; the rule (≥ 10 planned units and ≥ 25 commits a week over 90 days) picks basalt-ui, argo, weatherorb, shutterflow, dotfiles and warden. Everywhere else a session per task is cheaper and enough. Scheduling stays in code; mothers spend tokens only on judgment.

Will the factory eat my Max quota? Not by design, and it will not waste it either. Routine work stays on IU; the guard parks non-urgent Max work when the forecast for factory plus you reaches 100 % at the reset, with your reserve derived from your own p90 share (ADR-008). The inverse rule spends capacity that would lapse: 3 of 7 cycles peaked at 55–79 %, and when the forecast sits below 100 % − reserve − margin, non-urgent IU-class work spawns on Max. Measured as owner sessions blocked per cycle (target 0) and Max lapsed % (today p50 4 %, p90 30.6 %, kpi/forecast).

What still needs me? Product direction, spend, irreversible data loss, other people — as a card with options, a default and an expiry. Today 6 of 156 decision-relevant events in the golden set were genuinely yours; the SLO is under 1 % of items, the stretch 0.1 %.

What happens when the mini is down? Argo's VPS half says "mini unreachable since hh:mm"; the VPS dead-man's switch pushes to the phone after 15 minutes. Kuma cannot do it — it shares the mini's house and power.

Why did every previous model drift, and why would this one hold? Prose claims held 1 of 11; claims that code runs held 7 of 7. Here every invariant is a capability limit with a test, a CI check or a generated file — or it is labelled target. The doc-contradiction lint and the generated AGENTS.md block make drift fail CI instead of failing silently.

Can I still open a herdr tab and just work? Yes. The manual Claude Code + herdr lane is a rule of every wave, and rd wave keeps working after each one.

Does Slack go away? As an intake, at once — it stops with the old warden (W1) and the primary-source adapters replace it (W3). As a human channel it stays until Argo's notifications (W6), Hermes' briefings (W11) and the per-project changelogs (W13) replace what is posted there.

What does Hermes become? The conversational door: it answers from the factory's read models, files briefs as Tasks, steers agents and asks rd for sessions — through the same verbs as Argo. It loses every code tool (a capability limit with a test), its briefings are generated from the event log and delivered as Argo threads with audio, and the daily "Project narratives" cron that posts to Slack retires into per-project changelogs in the brain (W11, W13).

MCP or CLIs? CLIs, on one agent contract (ADR-004). Spike 4's only systematic CLI failure — headless polling on a long job, 95k tokens — was fixed by one policy sentence (2 calls, 38.9k tokens). Commands are defined once in code; help, docs, skill references and the AGENTS.md routing block are generated and drift-checked. MCP stays only for research-gateway (Claude Desktop) and chrome-devtools until a browser CLI exists.

How do we know the design works before building it? A golden set of 959 labelled events with pre-registered thresholds, a backtest that never tuned on its held-out half, a baseline gameday against today's system, and KPI scripts the loop cannot edit (section 7).

How long does the rewrite take? Fourteen waves in three lanes on a serial warden spine, ≈ 23 working days of wave time (waves.md Calendar); W1–W3 are fully specified and can start now (W1 and W2 in parallel). Raw alerts reach your Slack channel on days 1–5; verified shipping returns with W5 (day 11), full autonomous operation with W10 (day 23) — section 1b, During the rewrite.
