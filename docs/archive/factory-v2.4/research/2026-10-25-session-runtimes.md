## Bottom line

- **Runtime mechanism.** Four transports cover all fourteen tools: **tmux/PTY terminal wrapping** (Claude Squad, Gas Town, Superset, Conductor's bundled binary), **headless `claude -p` + stream-json** (Vibe Kanban, Sculptor, engrams), the **Claude Agent SDK** (T3 Code, Happy's remote mode) and **ACP** (T3 Code's Claude path for ACP agents, agent-orchestrator's Chat mode), with **Firecracker/Docker cloud sandboxes** for Cursor, Warp Oz and Omnara. Codex app-server is its own bidirectional JSON-RPC protocol, not any of these.
- **Authentication.** Subscription OAuth in third-party tools was squeezed four times between January and April 2026, but an individual running the **unmodified `claude` binary against their own Max/Pro login** — interactively, via `claude -p`, via `claude --bg`, or via a `claude setup-token` token — is still explicitly documented and permitted in Oct 2026; what is banned is a third party *offering* claude.ai login or *routing its users'* traffic through plan credentials, and since 4 April 2026 third-party apps draw from extra-usage credits while first-party surfaces keep plan limits.
- **Durability.** It degrades in a clean order: tmux-pane tools store no transcript and lose everything when the tmux server dies (Claude Squad), PTY-daemon tools survive app quit but not reboot (Superset), headless/SDK tools persist transcripts to SQLite and resume by session id (Vibe Kanban, T3 Code, Sculptor, agent-orchestrator), and VM tools rebuild from a snapshot plus an out-of-band event log (engrams Postgres `session_events`, Cursor's 30-day VM snapshots).
- **Steering.** Only PTY/tmux tools and Anthropic's own background supervisor accept true mid-turn input; `claude -p` and the Agent SDK are queue-only (a new prompt runs after the `result` event), and ACP/Codex app-server are the only third-party protocols with an explicit mid-turn steer RPC.
- **Failure modes.** The recurring ones are stale/revoked OAuth credentials that still report "authenticated", rate-limit collisions from unbounded fan-out, permission-approval requests that get stuck or are silently skipped, and crash-orphaned executions that are marked failed rather than reattached.
- **Converged pattern.** Worktree-per-session + append-only transcript/event log + out-of-band turn-end signal + a supervisor process separate from the UI + an attach channel, with credentials delegated to the user's own installed CLI.
- **Recommendation.** Keep interactive sessions, but replace the hand-rolled multiplexer with Anthropic's documented background supervisor (`claude --bg` + `claude agents --json` + `claude attach`), and use `-p`/stream-json only for scripted sub-steps; the Agent SDK is the wrong choice for personal Max usage because it is the one surface the policy targets.

## Anthropic's terms and enforcement, Jan–Oct 2026

**5–9 January 2026 — server-side block.** Anthropic began rejecting subscription OAuth tokens used outside Claude Code; the error text was `400 … "This credential is only authorized for use with Claude Code and cannot be used for other API requests."` A community write-up dates the switch to about 02:20 UTC on 9 January 2026 with no blog post or notice. A second wave is reported from 28 January 2026, and an individual account ban for ToS violation after OAuth use in a third-party client is reported as early as 5 January. Reports of a partial rollback after backlash rest on a single low-confidence account and should be treated as unconfirmed. ([falcao.org](https://falcao.org/posts/anthropic-claude-access-crackdown-ecosystem-fallout/), [joeyhipolito](https://joeyhipolito.substack.com/p/how-to-build-a-harness-anthropic), [opencode#10956](https://github.com/anomalyco/opencode/issues/10956))

**17–19 February 2026 — codified in documentation, not in a new contract.** What changed was the Claude Code *legal and compliance* docs page, which gained a "Usage policy" heading with an **unnumbered** subsection "Authentication and credential use", reading: *"OAuth authentication (used with Free, Pro, and Max plans) is intended exclusively for Claude Code and Claude.ai. Using OAuth tokens obtained through Claude Free, Pro, or Max accounts in any other product, tool, or service — including the Agent SDK — is not permitted and constitutes a violation of the Consumer Terms of Service."* The binding hook was already there: Consumer Terms §3, numbered item 7 — *"Except when you are accessing our Services via an Anthropic API Key or where we otherwise explicitly permit it, to access the Services through automated or non-human means, whether through a bot, script, or otherwise"* — which The Register reports was unchanged since at least February 2024, i.e. the February change was a clarification of §3.7, not a new term. An Anthropic staffer later called it a "docs clean up" that caused confusion. ([The Register, 20 Feb 2026](https://www.theregister.com/software/2026/02/20/anthropic-clarifies-ban-on-third-party-tool-access-to-claude/5014546), [consumer terms](https://www.anthropic.com/legal/consumer-terms), [gigazine](https://gigazine.net/gsc_news/en/20260220-anthropic-third-party-block/), [ACP issue #337](https://github.com/agentclientprotocol/claude-agent-acp/issues/337))

**10 February 2026 — the Agent SDK asymmetry documented.** SDK issue #559 records that "the Agent SDK requires API key authentication and explicitly prohibits using claude.ai subscription billing (Pro/Max)", while "`claude -p` (the CLI) does work with Max billing". ([claude-agent-sdk-python#559](https://github.com/anthropics/claude-agent-sdk-python/issues/559))

**3–4 April 2026 — subscriptions stop covering third-party tools.** Announced 3 April for 12:00 PT on 4 April: "starting tomorrow (April 4) at 12pm PT, your Claude subscription no longer covers usage on third-party tools". Anthropic's own corporate statement was an **emailed spokesperson reply to The Register**, not a published post: *"Starting April 4, third-party tools will draw from extra usage instead of subscription limits… Using Claude subscriptions with third-party tools isn't permitted under our Terms of Service, and they put an outsized strain on our systems."* Subscribers received an email (quoted by TechCrunch) saying they would "no longer be able to use your Claude subscription limits for third-party harnesses including OpenClaw", that the policy "applies to all third-party harnesses and will be rolled out to more shortly", and that continued use requires "a pay-as-you-go option billed separately from your subscription". No newsroom post exists — archived captures of anthropic.com/news on 5 and 10 April 2026 show nothing about it. Live error text: `400 … "Third-party apps now draw from extra usage, not plan limits…"`. ([The Register, 6 Apr 2026](https://www.theregister.com/software/2026/04/06/anthropic-closes-door-on-subscription-use-of-openclaw/5222854), [TechCrunch](https://techcrunch.com/2026/04/04/anthropic-says-claude-code-subscribers-will-need-to-pay-extra-for-openclaw-support/), [gsd-2#3772](https://github.com/gsd-build/gsd-2/issues/3772), [news archive](https://web.archive.org/web/20260410/https://www.anthropic.com/news))

Importantly, OpenClaw's repository records that Anthropic staff told them Claude CLI reuse and `claude -p` "is allowed again" (6 April 2026) — enforcement hit **OAuth credential reuse**, not invoking the real binary. That distinction is the crux of everything below. ([openclaw commit](https://github.com/openclaw/openclaw/commit/d378a504ac17eab2425a114fed32a217b5702395))

## What the Oct 2026 docs actually distinguish

**(a) Interactive Max/Pro login — protected.** OAuth "is intended exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications." End users may sign in "to the unmodified Claude Code binary with their own Claude subscription, including where a platform hosts Claude Code"; hosting requires the binary not be modified and no auth method removed or disabled. Note the wording shift: the February text said "Claude Code and Claude.ai", the current text says "Claude Code and other native Anthropic applications". ([legal-and-compliance](https://code.claude.com/docs/en/legal-and-compliance), [daily.dev summary](https://daily.dev/posts/anthropic-clarifies-ban-on-third-party-tool-access-to-claude-vor3aub97))

**(b) Headless `claude -p` / stream-json with a subscription — still supported.** `claude setup-token` mints a one-year OAuth token set as `CLAUDE_CODE_OAUTH_TOKEN`, which "authenticates with your Claude subscription and requires a Pro, Max, Team, or Enterprise plan. It can only make model requests, so it can't establish Remote Control sessions or fetch claude.ai connectors." It ranks below `ANTHROPIC_API_KEY`/`apiKeyHelper` and above the interactive `/login` credential in the precedence list. The exception is `--bare`: "In bare mode, Claude Code never reads OAuth credentials or the system keychain… Set `ANTHROPIC_API_KEY` before running it, because bare mode doesn't use your subscription login." ([authentication](https://code.claude.com/docs/en/authentication), [headless](https://code.claude.com/docs/en/headless))

**(c) Agent SDK — API keys, governed by Commercial Terms.** The overview note reads: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK. Use the API key authentication methods described in the Quickstart instead." That sentence was first added (rate-limits only) somewhere between 6 and 22 November 2025 with the platform.claude.com docs migration, gained "claude.ai login" in the 31 December 2025 restructure, switched to "Anthropic does not allow" by 20 February 2026, and now points at the Quickstart. SDK use "is governed by Anthropic's Commercial Terms of Service". ([agent-sdk overview](https://code.claude.com/docs/en/agent-sdk/overview.md), [2025-11-22 capture](https://web.archive.org/web/20251122185621/https://platform.claude.com/docs/en/agent-sdk/overview), [2025-12-31 capture](https://web.archive.org/web/20251231043608/https://platform.claude.com/docs/en/agent-sdk/overview), [2026-02-20 capture](https://web.archive.org/web/20260220222101/https://platform.claude.com/docs/en/agent-sdk/overview))

**The tension to name.** The same legal page says "Advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and the Agent SDK" — which reads more permissively than the SDK note — and reserves that "Anthropic reserves the right to take measures to enforce these restrictions and may do so without prior notice." The help centre (article dated Oct 2026) adds that Anthropic "may at its discretion allow paid subscribers who have enabled usage credits to use certain third-party tools… but reserves the right to draw use of such third-party tools from usage credits rather than subscription limits", and that tools which "misrepresent their identity to Anthropic's servers, attempt to route third-party traffic against subscription limits" are prohibited. The Commercial Terms themselves contain no OAuth-specific clause — only D.4 (no reselling) and D.2 (usage-policy compliance). ([legal-and-compliance](https://code.claude.com/docs/en/legal-and-compliance), [help centre](https://support.claude.com/en/articles/13189465-log-in-to-your-claude-account), [commercial terms](https://www.anthropic.com/legal/commercial-terms))

**The practical reading for a solo developer:** running your own sessions, on your own Mac, against your own Max login is what the docs sanction. Everything that broke in 2026 broke because a tool either (i) shipped its own OAuth client and reused your tokens server-side, (ii) set `ANTHROPIC_API_KEY` and silently moved you to API billing, or (iii) was a product *offering* claude.ai login to *other* people.

## The tools

### PTY / tmux terminal wrappers

**Claude Squad (smtg-ai/claude-squad, AGPL-3.0, v1.0.20 2026-08-20).** Runtime: one detached tmux session per instance with the agent CLI as the session command — `tmux new-session -d -s claudesquad_<name> -c <workdir> <program>`, `history-limit 10000` — attached by running `tmux attach-session -t <name>` inside a `creack/pty` PTY. State is *scraped*, not signalled: `tmux capture-pane -p -e -J`, sha256 change detection, substring matches on literals like `"No, and tell Claude what to do differently"`. Auth: it runs your own binary — `GetClaudeCommand()` sources `~/.zshrc`/`~/.bashrc` then `which claude` — so it never touches credentials, and Codex is expected to be pre-authenticated with `OPENAI_API_KEY`. Durability: tmux plus a JSON instance list under `~/.claude-squad/`; `InstanceData` has no transcript field, so conversation lives in pane scrollback and Claude's own session files; `ErrSessionNotFound` is modelled explicitly as what "happens whenever the tmux server dies (reboot, crash, `tmux kill-server`)". Steering: real keystrokes — `↵/o` attach, `ctrl-q` detach, `c` commit-and-pause, `r` resume, `s` push, plus an AutoYes daemon polling at 1000 ms. Failures: "`failed to start new session: timed out waiting for tmux session`" against a hard-coded 2-second timeout (cursorily fixed by updating the CLI); `Detach()` **panics** if closing the attach PTY fails; and auto-dismissing trust screens by matching exact CLI UI text ("Do you trust the files in this folder?", "(Y)es/(N)o/(D)on't ask again") is a heuristic any Anthropic copy change breaks. ([tmux.go](https://github.com/smtg-ai/claude-squad/blob/HEAD/session/tmux/tmux.go), [config.go](https://github.com/smtg-ai/claude-squad/blob/HEAD/config/config.go), [storage.go](https://github.com/smtg-ai/claude-squad/blob/HEAD/session/storage.go), [README](https://github.com/smtg-ai/claude-squad/blob/HEAD/README.md))

**Gas Town (steveyegge/gastown → now gastownhall/gastown, MIT, v1.2.1 2026-06-06).** Runtime: pure tmux wrapping with no agent-library linkage at all — "Gas Town launches agents in tmux sessions and communicates via `send-keys`", liveness via `tmux display-message -p '#{pane_current_command}'`, output via `capture-pane`, readiness by prompt-prefix scan (e.g. `❯ `) or `ready_delay_ms`. Claude hooks are installed through `--settings`: SessionStart `gt prime --hook && gt mail check --inject`, UserPromptSubmit `gt mail check --inject`, PreCompact `gt prime --hook`, PreToolUse `gt tap guard pr-workflow`, Stop `gt costs record`. A headless `-p` path exists only for formulas and "dogs" via the `non_interactive` preset field. Auth: not documented anywhere; it delegates to whatever `claude` is logged in as. Durability: git worktrees, a Beads/Dolt ledger, `gt seance` to find predecessor sessions via `.events.jsonl`, and `--resume` as the preset `resume_flag`. Steering: `gt mayor attach`, `gt nudge`, `gt feed --problems` with `n` to nudge and `h` to handoff. Failures: the scheduler exists specifically to prevent "API rate limit exhaustion" by batching polecat dispatch under `scheduler.max_polecats`; "Zombie = Dead tmux session" is a first-class health state; the Refinery is a Bors-style bisecting merge queue because "polecats never push directly to main". Gas Town's own docs describe `send-keys`/`capture-pane` as heuristics to be replaced — the successor Gas City formalises an explicit `AgentProvider` interface (Start/IsReady/IsAlive/SendMessage/GetStatus/Resume/ForkSession/Exec). ([agent-provider-integration.md](https://github.com/gastownhall/gastown/blob/HEAD/docs/agent-provider-integration.md), [README](https://github.com/gastownhall/gastown/blob/HEAD/README.md))

**Superset (superset.sh, Elastic License 2.0).** Runtime: PTY-based, not container-based, and the most carefully engineered PTY story in the set — agent terminals are owned by a **detached terminal daemon** (Electron run as Node via `ELECTRON_RUN_AS_NODE=1`, node-pty host) speaking NDJSON over Unix domain sockets with a two-socket split (stream vs RPC) to avoid head-of-line blocking, plus a headless xterm.js emulator per session for accurate re-attach snapshots and CWD via OSC escapes. They tried tmux first and moved away from it. Isolation is git worktrees only, and the vendor says so: "Worktrees separate working files, but do not sandbox processes or prevent merge conflicts." Auth: it "never proxies model API calls; you bring your own agent subscriptions and API keys"; Claude Code launches as `claude --dangerously-skip-permissions` with approvals off by default, and a Usage page shows quota meters, token costs and multiple Claude accounts. Durability: closing windows, ⌘Q and app updates do **not** kill agents; "Quit Superset Completely", restart and logout do; a daemon crash is recovered by cold restore from disk history; resume is `--resume`, fork is `--fork-session`; the standalone CLI host (`superset start --daemon`) keeps a machine reachable. Steering: typing into the live PTY from any of several attached windows, plus a "handoff" that moves a conversation with Claude's transcript to another agent. ([terminal-daemon-deep-dive](https://superset.sh/blog/terminal-daemon-deep-dive), [keep-agents-running](https://docs.superset.sh/keep-agents-running), [claude-code](https://docs.superset.sh/agents/claude-code), [llms.txt](https://superset.sh/llms.txt))

**Conductor (conductor.build).** Runtime: local agents in git worktrees on the Mac (`CONDUCTOR_IS_LOCAL=1`) or Linux cloud sandboxes (`=0`), unsandboxed locally — "Agents run directly on your system without sandboxing", with a dedicated machine or VM as the recommended mitigation. It ships its **own** Claude Code and Codex executables at `~/Library/Application Support/com.conductor.app/bin` and injects system prompts. **The transport (PTY vs stream-json) is not documented on any page read** — that remains the biggest gap in this comparison. Auth: pass-through — "By default, Conductor uses the auth tokens already saved on your machine. If you're logged into Claude Code with an API key, Conductor uses that; if you're logged in with Claude Pro or Max, Conductor uses that", overridable per agent, with an explicit warning that a set `ANTHROPIC_API_KEY` "may" be used instead of subscription usage, resulting in API charges. Durability: checkpoints captured as private Git refs before each agent turn, stored locally; reverting a turn permanently deletes all messages from that turn on plus all code changes since. Steering: "Big Terminal Mode" (a full terminal in the centre panel), Remote Control from the iOS app, and cloud workspace SSH/terminals. ([FAQ](https://www.conductor.build/docs/faq), [claude-code harness](https://www.conductor.build/docs/reference/harnesses/claude-code), [checkpoints](https://conductor.build/docs/reference/checkpoints), [SKILL.md](https://www.conductor.build/.well-known/agent-skills/conductor/SKILL.md), [llms.txt](https://www.conductor.build/llms.txt))

### Headless `claude -p` + stream-json

**Vibe Kanban (BloopAI, Apache-2.0) — sunsetting.** bloop shut down; the repo continues "open source and community maintained", remote services (kanban issues, comments, projects, organisations) survive 30 days before the app moves to "a fully local architecture", and "local workspaces will continue to function". Code floats ~5 months ahead of the last tag (`v0.1.44-20260424091429`, 2026-04-24) with 542 open issues. Runtime: run `npx -y @anthropic-ai/claude-code@2.1.119 -p --verbose --output-format=stream-json --input-format=stream-json --include-partial-messages --replay-user-messages` with all three stdio piped, then drive it through a bidirectional **control protocol** (`ProtocolPeer` + `ClaudeAgentClient`) calling `initialize(hooks)`, `set_permission_mode(...)`, `send_user_message(prompt)`. Ten-plus agents sit behind a `StandardCodingAgentExecutor` trait. Auth: it holds no credentials — "logged in" is inferred from the mtime of `~/.claude.json` (`AvailabilityInfo::LoginDetected`) — but it npx-pins the CLI version rather than using your install, has a `disable_api_key` flag doing `command.env_remove("ANTHROPIC_API_KEY")`, and injects a warning when Claude reports `api_key_source == "ANTHROPIC_API_KEY"`: "Usage will be billed via Anthropic pay-as-you-go instead of your Claude subscription." Durability: server-backed SQL with `workspace`, `session`, `execution_process`, `execution_process_repo_state`, `coding_agent_turn` tables; each attempt carries per-repo `before_head_commit`/`after_head_commit`; transcripts replay from the DB via `load_raw_log_messages` + `normalize_logs`; crash-orphaned attempts are marked `Failed` at startup by `cleanup_orphan_executions` with **no reattach**. Resume is `--resume <session_id>` optionally with `--resume-session-at <uuid>`; rewinding uses `reset_session_to_process` (reconcile worktree to the commit, then `drop_at_and_after`). Steering: a follow-up prompt spawns a *new* resumed process; approvals are `PreToolUse` hooks via `--permission-prompt-tool=stdio` with plan mode auto-approving everything except `^(ExitPlanMode|AskUserQuestion)$`. ([shutdown](https://www.vibekanban.com/blog/shutdown), [claude.rs](https://github.com/BloopAI/vibe-kanban/blob/HEAD/crates/executors/src/executors/claude.rs), [container.rs](https://github.com/BloopAI/vibe-kanban/blob/HEAD/crates/services/src/services/container.rs), [README](https://github.com/BloopAI/vibe-kanban/blob/HEAD/README.md))

**Sculptor (Imbue, MIT, v0.49.0 2026-10-21).** Runtime: one local Python/FastAPI backend with an Electron thin client and a `sculpt` CLI over the same HTTP + live-update-stream API. Claude runs "as a streaming JSON process with its control protocol enabled, so Sculptor can both read Claude's events and ask it questions mid-session. Claude runs sandboxed, with tool permissions auto-approved." Sculptor substitutes its own AskUserQuestion/ExitPlanMode tools, registers a pre-compaction hook, and queries context-window usage at the end of every turn; Pi runs in RPC mode. A separate PTY path exists for registered "terminal agents" (TOML `launch_command`/`resume_command_template`, hooks calling `sculpt signal`). **Version caveat: per-agent Docker containers are historical.** Imbue's March 2026 blog said "Sculptor runs every agent in its own Docker container for true isolation", and third-party coverage repeated "one Docker container per agent, full stop" — but in the Oct 2026 tree Docker is the experimental *custom backend command* that relocates the entire backend into a container/remote, and the spec states it "is not a per-workspace isolation mode". Current isolation is a git worktree per workspace, with **all agents in one workspace sharing one working copy and no locking**. Auth: Claude CLI sign-in (including paste-a-code for headless) or `CLAUDE_CODE_OAUTH_TOKEN` from `claude setup-token`; no bundled keys; for a containerised backend on macOS it explicitly recommends minting a long-lived token and forwarding `CLAUDE_CODE_OAUTH_TOKEN` in. Documented auth failure: "`claude auth status` reports success on the token's presence without validating it, so a revoked or expired token shows as authenticated while agent runs fail." Durability: "an interrupted turn survives a quit, or a crash of Sculptor itself"; reopening restores workspaces, agents and full history; a running agent is reattached and resumed "wherever that's possible"; pending questions survive reload and harness restart; data is a local SQLite store with append-only snapshot log and Alembic migrations under `~/.sculptor/workspaces/<id>/code`. Steering: stop (Ctrl+C), an editable message queue, "interrupt-and-send", a question panel, and `/btw` for a read-only side answer from a Haiku fork; terminal agents get a draft action that types into the PTY without Enter. Failures: same-workspace agent collisions (the docs tell you to keep agents on separate concerns), "identity entered twice" and unreachable macOS keychain in the container path, manual restart required after changing the backend command, and the whole product flagged as an "experimental research preview" that is a local server — so agents and the CI babysitter only work while the machine is on. ([integrated_harnesses.md](https://github.com/imbue-ai/sculptor/blob/HEAD/docs/help/integrated_harnesses.md), [container_backend.md](https://github.com/imbue-ai/sculptor/blob/HEAD/docs/help/experimental/container_backend.md), [SPEC.md](https://github.com/imbue-ai/sculptor/blob/HEAD/docs/specs/SPEC.md), [workspaces.md](https://github.com/imbue-ai/sculptor/blob/HEAD/docs/help/workspaces.md), [Imbue blog](https://imbue.com/blog/containers), [byteiota](https://byteiota.com/sculptor-by-imbue-run-parallel-ai-coding-agents-without-port-conflicts/))

**engrams (cortexapps/engrams, AGPL-3.0, v0.11.0 2026-10-19).** Runtime (as established): headless `claude --print --input-format stream-json` inside Firecracker VMs, with in-guest `engram-agentd` PID 1 after `/sbin/engram-init`, vsock :1024, driven by a Bun/DBOS host service; the harness child is killed and re-exec'd on resume as a "clean re-spawn point". Auth: a documented split — "either connect your Claude Code token for interactive sessions or add an org secret named `ANTHROPIC_API_KEY` for sessions started from the CLI and other automations"; the `session_secrets` table stores "sealed per-request overrides (e.g. `CLAUDE_CODE_OAUTH_TOKEN`) needed to rebuild the harness env on cold resume". Durability is the strongest here: Postgres `session_events` is an append-only conversation + tool-call log keyed `(session_id, idx)` driving SSE replay, independent of the VM; VM disk+memory live as sha256-keyed chunks with versioned manifests; idle → snapshot → destroy → `Idle` → next prompt triggers `ensure_active` auto-resume (hot UFFD, or cold download/untar/restore on any host), `Dead` → 410 Gone. Steering: `send_prompt`/`bind_session` are host-level, and ADR 0054 routes harness `AskUserQuestion` to the UI; true mid-turn steering is not documented. Failures: DESIGN.md contradicts itself on vsock auth ("the agent currently does not authenticate connections") and on host-loss tolerance ("no cross-host failover"), and the project warns it is 0.x, carries a daily-rebased Firecracker fork, has no container mode, and treats multi-tenancy hardening as a non-goal. ([README](https://github.com/cortexapps/engrams/blob/HEAD/README.md), [DESIGN.md](https://github.com/cortexapps/engrams/blob/HEAD/DESIGN.md), [ADR 0054 commit](https://github.com/cortexapps/engrams/commit/b0d2bd979a4ad97715cd77e87b63f17afe43d405), [DBOS webcast](https://www.dbos.dev/webcast/cortex-software-factory))

### Claude Agent SDK

**T3 Code (pingdotgg/t3code, MIT, v0.1.2 2026-10-22).** Runtime: a server + thin clients ("agent harness control surface") whose Claude driver is a native adapter over the Agent SDK — `apps/server/package.json` pins `@anthropic-ai/claude-agent-sdk ^0.3.276` alongside `node-pty ^1.2.0-beta.15` and `stream-json 3.6.0`, and the provider docs say "Claude's SDK mode emits no goal events; its adapter reads goal state from the synthetic command output and Stop hook feedback in the transcript." A second path runs Claude as an ACP agent ("Claude Agent uses the ACP v2 preview by default for Registry and local `claude-agent-acp` commands"; `CLAUDE_AGENT_ACP_EXPERIMENTAL_V2=0` forces v1). Spawning is a durable command/effect pipeline: the `EventSink` commits event + projections + command receipt + outbox in one DB transaction, then `EffectWorker` performs the spawn. ## The converged pattern

Six things recur in every tool that works, and their absence predicts the failures:

1. **A git worktree per session** — Conductor, Superset, Claude Squad, Gas Town (hooks), Vibe Kanban, Sculptor, Orchestrator, and Claude Code itself (`.claude/worktrees/`). The corollary failure is Sculptor's shared working copy: "All agents in a workspace share the same working copy", so two agents editing one file collide.
2. **An authoritative append-only transcript or event log** outside the agent process — SQLite under `~/.t3/userdata`, Postgres `session_events`, Vibe Kanban's `execution_process` rows, Codex rollout JSONL. Claude Code's own `~/.claude/projects/<project>/<session-id>.jsonl` is the shared substrate, and Anthropic warns its "entry format is internal… and changes between versions, so scripts that parse these files directly can break on any release."
3. **An out-of-band turn-end signal** — the `result` line for `-p`/stream-json, a `Stop` hook, `state: done` from Claude's own `claude agents --json`, or Codex's `turn/completed`. Anything scraping a rendered TUI (Claude Squad, Gas Town) is doing the fragile version of this.
4. **A supervisor process distinct from the UI** — Superset's terminal daemon, T3's systemd/launchd service, Orchestrator's detached per-session hosts, Anthropic's own `claude --bg` supervisor. The failure it prevents is exactly what Happy has: the CLI process *is* the runtime, so a laptop sleep ends the turn.
5. **A dedicated attach/steer channel**, and an explicit answer to "is steering queued or injected" — queue-only in Happy, Vibe Kanban, T3 and `claude -p`; injected in Claude Squad, Superset, Gas Town, Claude Code interactively; a first-class RPC in Codex and an interface handoff in Orchestrator.
6. **Credential delegation to the user's own installed CLI/login.** Every tool here except Warp Oz, Cursor and Omnara refuses to hold model credentials — which is precisely why most of them survived April 2026. The ones with an `ANTHROPIC_API_KEY` escape hatch (Vibe Kanban, Conductor, T3) all ship a warning, because the failure is silent billing.

## Recommendation for a solo dev on a home Mac mini under Max

**Keep interactive sessions. Do not switch to `-p` stream-json as your primary loop, and do not build on the Agent SDK.** But drop the hand-rolled multiplexer in favour of the supervisor Anthropic now documents.

Anthropic's own CLI reference adds a **fourth option** your three-way framing misses: background sessions under a supervisor — `claude --bg "<prompt>"`, then `claude agents` / `claude attach <id>` / `claude logs` / `claude stop` / `claude respawn` / `claude daemon status`. Each is "a full Claude Code conversation that keeps running without a terminal attached", hosted by "a separate supervisor process… so you can close agent view, close your shell, or start a new interactive session and your dispatched work keeps going." Note `--bg` is rejected when combined with `-p`. ([cli-usage](https://code.claude.com/docs/en/cli-usage), [agent-view](https://code.claude.com/docs/en/agent-view))

Why this beats both alternatives for your specific workload (investigate → plan → build → test → deploy → verify production):

- **Auth is free and sanctioned.** "The supervisor and its sessions authenticate with the same stored credentials as your interactive sessions." No `setup-token` plumbing, no API-key billing risk, no exposure to the SDK prohibition. Your Max subscription is the intended funding source for exactly this.
- **The reaping/resuming you would otherwise build is already specified**: sessions idle-and-unattached are stopped after "about an hour" (Ctrl+T pins them), sessions that "exited unexpectedly while the supervisor is running" are restarted, machine sleep is handled ("their processes resume on wake", and an unresponsive session is restarted and "continues the interrupted response from where it left off"), and after a full shutdown a session shows `failed` within 48 hours then `stopped`. The one window you must design around: if the supervisor dies, "your sessions stop unless a new supervisor connects within about a minute."
- **`claude agents --json` is the sanctioned replacement for your hooks-based turn reporting.** Entries carry `state` (working/blocked/done/failed/stopped), `status` (busy/waiting/idle) and `waitingFor`, plus `sessionId` — and the docs explicitly say the underlying `~/.claude/jobs/<id>/` files are "not a stable interface". That is a strictly better contract than parsing hook payloads.
- **Worktree isolation is automatic**: "Before editing files, Claude moves the session into an isolated git worktree under `.claude/worktrees/`" (`worktree.bgIsolation: "none"` opts out).
- **Steering matches what you have now**: replies from the peek panel to a working session "join the session's message queue instead of interrupting the response", while a reply that is exactly `/stop:` stops it at once; `/model`, `/effort`, `/usage` run immediately.

Keep `claude -p` for scripted sub-steps that need structured output — it is the one place where `--include-partial-messages`, `--output-format json` with `total_cost_usd`, and `system/api_retry` events (`attempt`, `max_retries`, `retry_delay_ms`, `error` category including `rate_limit`/`overloaded`) earn their keep, and the `result` line is the documented turn end. Two hard rules if you do: send **SIGINT** not SIGTERM to end a turn ("SIGTERM… exits with code 143. Claude Code leaves the turn that was in progress unfinished and records no result for it"), and remember that from v2.1.302 `claude -p` starts in **Manual** mode — anything needing approval is denied unless a `PermissionRequest` hook or `--permission-prompt-tool` approves it.

Avoid, for a personal Max setup: the Agent SDK as your loop (the note targets it by name, and Anthropic's own docs say "don't rely on session resume — capture the results you need as application state"), `--bare` (never reads OAuth — needs `ANTHROPIC_API_KEY`), and `--dangerously-skip-permissions` as a default (it is `bypassPermissions`, and the unsandboxed-retry escape hatch then "runs without a prompt").

Guardrails worth wiring: never let two processes write one transcript (resume in two terminals without `--fork-session` and "messages from both interleave"); re-pass `--mcp-config`/`--settings`/`--plugin-dir`/`--fallback-model`/`--add-dir` on resume, since they are not restored; expect an interrupted tool call **not** to be re-run on resume (it is marked cut off and Claude is told to check whether it took effect) unless `CLAUDE_CODE_RESUME_INTERRUPTED_TURN` is set; and set `cleanupPeriodDays` deliberately, because transcripts default to 30-day retention. Finally, if you ever want per-project isolation without a substrate change, `claude --worktree` / `-w` plus `--tmux` is the in-CLI equivalent of what herdr is doing for you.

If you later distribute the harness to other people, the calculus inverts completely: you become the third party, the SDK note applies to you, and API keys become mandatory — that is the line the whole 2026 sequence drew.
